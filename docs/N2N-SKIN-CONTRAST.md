# Naara chat x skins: how contrast is enforced (MASTER-ONLY)

**The rule.** In the Naara chat shell (every tab, sheet, panel, menu and card) text must reach **7:1 below 14px, 5.5:1 from 14px, 4.5:1 for large text**, in every one of the 35 skins, both modes and every accent. That is stricter than WCAG AA on purpose: members read this app on phones in sunlight.

**How it is built**
- `resources/css/nx-chat-skins.css`: each skin's signature on the chat's own parts (clay raised, neo hard outline, passport stamped serif, paper ruled notebook, dot grid, aurora glow) plus the legibility floor. Colours come from tokens only; a member's custom chat theme still wins.
- `--cs-acc`: the skin's accent deepened (58% accent, 42% black) so white text on it always passes. Used for event/live cards, chosen poll options, active chips, document icons.
- `resources/css/nx-chat-contrast.css` is GENERATED by `node scripts/gen-chat-contrast.mjs` (dev server up). For every skin and mode it computes `--nx-text-2` / `--nx-text-3` inside `.nn` so secondary text keeps >= 7.2:1 on that skin's own canvas and surfaces. Re-run it whenever a skin's palette changes.
- The default skin's brand-teal/navy light palette (`nx-layout.css`) is scoped to `html[data-nx-skin=surface]`; every other skin supplies its own palette.

**How it is tested.** `node tests/visual/n2n/skin-contrast.mjs --scene=all [--skins=a,b] [--accents=teal,rose] [--mode=dark]` flips every skin x accent x mode on live pages and panels (thread, 9 side panels, menus, context menu, selection, request chat, new chat, More sheet, Updates, Calls, People, Credits, My profile, Naara ID) and measures real contrast on every text node, resolving gradients and translucent layers. Disabled controls are exempt. It must print `failing text elements: 0`.

**Non-text contrast (added 2026-10-05).** The same auditor now also checks every visible icon (3:1 against what is behind it; multi-colour brand artwork such as payment logos and flags is skipped) and the edge of every form field and composer whose fill does not already separate it from its surroundings (3:1). `--nx-edge` is generated per skin and mode by `scripts/gen-chat-contrast.mjs` (>= 4:1 against the skin's canvas and surfaces, so a tinted card still clears 3:1) and consumed by `nx-chat-skins.css` and `nx-contrast-floor.css`. The forward panel is its own scene (`ctx-forward`).

**Whole-app scan.** `tests/visual/skins/dom-pages.mjs` runs the same audit (WCAG AA: 4.5:1, 3:1 for large text) over any list of member or admin pages (`ROLE=admin|member URLS=... SKINS=... ACCENTS=...`). Image-backed heroes, preloader previews and glass sample tiles are skipped (judged on pixels elsewhere or fixed artwork). `resources/css/nx-contrast-floor.css` holds the global fixes it found (field edges, avatars, glass, the Trix toolbar). Accent fills (`cta_a`, `cta_b`, `acc_a`, `acc_b`) and light-mode `teal_ink` in `config/appearance.php` are generated to keep white text >= 4.5:1; re-run `python3 scripts/nx_accents.py` after editing them.

**Known blind spots.** The auditor cannot see `box-shadow` fills (use a real `background-image` overlay when you need to darken something); aurora and grain pseudo-layers are under 30% alpha and ignored. Real-device sunlight is untested.
